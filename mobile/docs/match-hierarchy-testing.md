# Match hierarchy phone checks

Use the updated app on the same installation as the previous version to check migration. Keep its existing local storage. A fresh installation can check creation but has no standalone stages to migrate.

1. Before updating, save at least two standalone stages with recognizable names. In one, save a fractional stage width, a moved target, a wall port, a manual route and a magazine/loadout. Record their visible values for comparison.
2. Open the updated app → Stage Planner. Expect Matches with one **Imported Stages** card, family **USPSA**, and the old stage count. Open it, then open each old stage. Confirm geometry, Stage Settings dimensions, route assignments and ammunition still match. Close/relaunch twice; there must still be one imported match and no duplicate stages.
3. Return to Matches → **+ Create Match**. Leave the name empty: creation must be disabled. Enter **Weekend A**, choose **USPSA**, then **Create Match**. Expect the match's empty stage list with **Back to Matches**. The form must contain only match name and target family.
4. In Weekend A, tap **+ Add Stage**, enter **Stage 1**, then **Open Stage Designer**. No dimensions should be requested. Open **Stage Settings** and confirm the default is approximately **13.333 yd × 10 yd**. Set width to **13.125** and depth to **10.25**, apply, and save. Return using the designer's Back button; expect Weekend A's stage list. Its match card must now show one stage.
5. Open Stage 1 → **Add**. USPSA must be selected under Target family. Add a cardboard target, open **Edit**, and confirm **Target family: USPSA**. Record its position and face dimensions, then Save → Back → Back to Matches. On Weekend A tap **Rename / Target family**, rename it to **Weekend A renamed**, choose **PCSL**, and **Save match**. Reopen Stage 1: the old target must remain USPSA at the same size/position. **Add** must now default to PCSL; add another cardboard target and check its family is PCSL. Save. Repeat the family switch to IDPA and confirm only newly added targets get IDPA. The existing prototype shapes/dimensions are shared; family-specific dimension presets are not part of this change.
6. Create **Weekend B**, choose **IDPA**, then add another **Stage 1**. Return to Matches. Open both matches and confirm each has its own Stage 1 and correct stage count. Editing Weekend B's stage must not change Weekend A's stage.
7. Inside Weekend B, **Rename stage** → enter **Stage 1 renamed** → **Apply name**. **Duplicate stage** should create **Stage 1 renamed (copy)** in Weekend B. Open and edit the copy, Save, then reopen the original and confirm it did not change. **Delete stage** → **Keep stage** must keep it. Repeat → **Confirm delete stage** must delete only that chosen stage and update the count.
8. Return to Matches → **Duplicate match** on Weekend A renamed. Expect **Weekend A renamed (copy)** with the same family and stage count. Edit a stage in the copied match and confirm the original remains unchanged. **Delete match** → **Keep match** must retain it. Repeat → **Confirm delete match** must remove the copy and its stages only. Weekend A, Weekend B and Imported Stages must remain usable.
9. Close/relaunch the app. Confirm match names, target families, stage counts and stage ownership persist. Open Weekend A's Stage 1: the fractional dimensions, old/new target families, route and loadout must persist. Modify its name without saving, press Back, choose **Keep editing**, then Back → **Discard changes and close**; expect that match's stage list with the saved name.

Native UI/keyboard/gesture verification is manual. Automated tests cover SQLite migration/reopen, exact payload preservation, isolation, family immutability, duplication, and transaction rollback; they do not certify phone interactions.

# Storage behavior

- Database schema version 2 adds a separate `matches` table and indexed `stages.matchId` relationship. StageDocument and plan stay exclusively in each stage's existing payload.
- On initialization, only stages with a null/empty matchId are associated with the reserved `imported-stages` match. It is created only when needed, named Imported Stages, with USPSA as its default family.
- Migration runs in a transaction and changes no stage ID, timestamp or payload bytes. It does not decode or rewrite geometry, routes, ammunition or unknown saved references. Even unreadable payloads stay stored and listed.
- Repeated initialization and reopening cannot duplicate imported matches or stages; renaming/changing the imported match's family does not undo the association. An intentionally deleted imported match is not recreated when no unowned stages remain.
- Creating new stages requires an existing match. Match updates never write stage payloads. Match deletion and duplication run atomically in the same write queue as stage/training writes. Duplicates get new match/stage row IDs; internal object/route IDs remain local to their copied stage.
