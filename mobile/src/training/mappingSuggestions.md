# Phase 8F-B mapping suggestions

`mappingSuggestions.ts` is a deterministic, bounded suggestion layer. It reads the comparison's historical snapshot and freshly analyzed confirmed timeline, never video frames, provisional detector proposals, a live route, or the active performance profile. Generation does not create authoritative mappings.

Observed units retain original interval/event IDs, timestamps, durations, shot counts, string IDs/counts, intersecting reload IDs, source references and timeline completeness. Position intervals require confirmed entry/exit; movement and reload definitions come from `observedExecution`. Strings retain their confirmed groups, including single-shot groups with zero duration. Confirmed total intervals supply start/end completeness. Exact duplicate position-transition/movement spans prefer explicit movement. Overlapping evidence types remain separate.

Planned units preserve route order, position IDs, evaluator movement distance/timing, engagement timing, target assignments, required rounds, reload placement/overlap and historical revision/version. Full dwell time remains unavailable. Target assignments are planned context, not inferred observed identities. Planned string count is unknown; observed strings are aggregated against known planned rounds rather than an invented planned string count.

Alignment uses K-best monotone dynamic programming in position, movement, string and reload lanes. Separate lanes permit overlapping dwell, engagement and reload evidence. Every match and combined candidate passes the existing comparison's compact mapping-order/overlap validation against fixed anchors. Skips and extras have centralized penalties; type mismatch and order reversal are prohibited. Combining lanes is a bounded heuristic, not a globally optimal joint alignment. Conflicting pairs are left explicitly unmatched. Up to eight consecutive strings can map to one position; confirmed movement or an intervening stable stop blocks merging. Up to three stable fragments within 250 ms may merge if no confirmed movement separates them. A single observed interval is never assigned to multiple planned positions; indistinguishable merged planned stops remain unmatched.

Duration difference is normalized by the larger duration and has less weight than skipping a planned unit. Counts and expected reload overlap add support. Confidence also uses coverage, unmatched observations, completeness and evidence quantity; sparse or incomplete evidence stays LOW. HIGH requires at least five pairs including movement and strings, high coverage/score, complete observed totals and no extra observations. Individual pair confidence is deliberately capped at MEDIUM: sequence evidence cannot prove stage identity. Reasons are deterministic strings, capped per pair.

All bounds and penalties live in `MAPPING_CONFIG`: 100 planned units, 240 observed units, 25,000 DP cells, 60,000 evaluated operations, four paths per cell, three diverse alternatives, eight reasons. Bounds return a visible failure instead of applying partial results. Valid existing confirmed mappings, including previously accepted suggestions, anchor subsequent generation. Missing anchors remain stored with a review warning. Conflicting anchors stop generation. Accept-all is atomic; any new conflict prevents replacement of user mappings.

Review is embedded in Compare to Plan. Preview selects the read-only route marker/incoming segment and highlights the confirmed interval rows, seeking the existing video timeline. Users may accept all pending pairs, accept/reject individually, or load any pair into the manual mapping editor. Manual string/position editing supports selecting multiple intervals. Generation, decisions and accepted rows persist with the existing comparison JSON and Save analysis.

Multi-string mappings store original IDs and resolve against the current confirmed timeline. Existing comparison calculations compare the first-to-last span, including transitions, with the evaluator's engagement estimate. Results separately retain each string, total shots, string count and summed within-string duration. Reload overlap and residual accounting use the existing comparison engine. No flattened groups are written to video analysis.

Suggestion metadata stores algorithm/config/comparison/video-analysis/snapshot versions, historical revision, timestamp and an input fingerprint covering the snapshot, video bounds and trusted events including grouping metadata. Timeline changes make the saved set stale when read and block acceptance; provisional detector changes do not. Unsupported or malformed suggestion payloads require regeneration. Manual mappings are retained and resolved by the existing comparison validity rules.

Limitations: conservative sequence evidence cannot recognize arbitrary positions, targets, or camera geometry. Missing stable endpoints cannot fabricate dwell. Reload association is temporal intersection, not a new reload timing model. Partial videos and repeated similar stops may have no reliable suggestion. Device interaction is not verified by unit tests.
