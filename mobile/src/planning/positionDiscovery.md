# Automatic position discovery (Phase 6A)

`discoverCandidatePositions(stage, config?)` is a pure, opt-in module. It neither imports UI code nor changes the manual plan, candidate generator, evaluator, ranking or storage. `toShootingPosition` returns a fresh existing `ShootingPosition` with inferred visible IDs and no engagements. Phase 6B must explicitly choose a pool for the existing generator (currently at most 12 positions); this module does not integrate that pipeline.

All geometry uses existing stage inches, X-right/Y-down coordinates and rotation. A deterministic row-major grid samples cell centers throughout the stage, with nominal maximum cell width/depth of 36 inches. The grid coarsens uniformly when necessary to fit the sample budget. Thin/asymmetric stages still stay within that budget. Start is optional distance context; it is not inserted as a candidate or asserted to be a shooting location. A grid point can independently coincide with Start.

Schema 7 has bounds, wall rectangles and fault-line markings, but no legal shooting-area polygon. Bounds and full rotated wall footprints determine usable points. Port footprints remain occupied for standing. No body radius, stand/base volumes, reachable path from Start, competition rules or fault-line interior is inferred. Returned reachability is explicitly NOT_EVALUATED. A disconnected area can therefore contain candidates.

LOS intersects a candidate-to-active-target-center segment with each rotated wall rectangle in wall-local physical coordinates, including wall thickness and tangencies. Solid contact blocks. A segment crossing a wall passes only when its entire intersection fits strictly within a single valid port's horizontal span. Projected ports are an explicit 2D approximation: sill/height are validated but cannot establish vertical firing clearance without muzzle elevation. Overlapping ports at different elevations are not combined into an invented aperture. Wall height/elevation does not permit firing over or under walls in this approximation. Target faces/no-shoots do not occlude other targets, and target facing is ignored. Existing `shootingDifficulty` uses target reference distance, including for partial faces; LOS uses the active face center via the existing geometry helper.

All scoring objects are required, matching the planner. No-shoots are excluded. Target limits and malformed targets retain the full scoring-target coverage denominator, so coverage cannot silently become 100% after dropping targets. Invalid walls/unknown objects stop discovery rather than inventing free space; invalid ports remain solid. Missing Start and no walls are supported. Invalid configuration/documents return warnings and empty results.

Each result includes stable grid IDs, stage positions, AUTO_DISCOVERED source, visible target IDs/count, ratio/percentage, per-target distances and difficulty, min/mean/max distance, total/average existing difficulty, optional distance from Start, warnings and search counters. LOS budget counts candidate-target checks, each inspecting at most the bounded wall collection; a candidate is retained only after its entire considered-target visibility pass completes.

Deduplication orders by coverage, lower average difficulty, Start proximity and coordinates. It merges only points within 48 inches with identical visible target sets and per-target difficulty differences at most 0.5. Comparing every target prevents averages from hiding opposing shot tradeoffs. Farther locations and materially different difficulty survive clustering. Output truncation can still remove useful alternatives and explicitly warns; no global optimality or full target coverage is promised.

Central defaults/hard ceilings: 2,048 samples, 64 output positions, 32,768 candidate-target LOS checks, 64 considered targets, 512 input objects and 32 ports per wall. Callers may lower ceilings but cannot raise them. Grid spacing (minimum 1 inch), deduplication radius and difficulty tolerance are configurable. Input object/port overflows stop before geometry processing; sampling/LOS/output limits retain completed useful candidates. Memory and geometry work are bounded. Coarse sampling can miss narrow useful areas or all useful areas; no result is proof of infeasibility.
